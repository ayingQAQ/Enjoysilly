# 稳定性回归

本轮是长期路线图的 v0.4 稳定性工作批次，不是 v1.0 发布。路线图见 [计划](plans/2026-10-29-reliability-roadmap.md)。现有包版本保持 0.3.0，不因测试通过自动打版本标签。

## 本地执行

```sh
npm install
npm test
npm run build
npm run preview -- --host 127.0.0.1 --port 4174
```

在另一个终端运行 `npm run test:browser`。默认使用已安装的 Microsoft Edge，无需真实 API。

PowerShell 下验证 Chrome：

```powershell
$env:E2E_BROWSER_CHANNEL = 'chrome'
npm run test:browser
```

可设置 `E2E_BASE_URL` 指向独立的本地生产预览。浏览器检查为每次运行新建隔离 context，不读取日常浏览器资料；所有模型请求在本地拦截。需要项目提供的 `test-fixtures/红楼.png` 和 `test-fixtures/【DarkSide-小猫之神】v2test.json`，这些真实样本按仓库约定不提交。

## 本轮覆盖

- 串行保存、同会话存档 ID 复用、旧会话异步结果隔离、保存中内容变化、失败后手动重试。
- 事务内存档版本检查；角色卡、世界书、预设过期草稿拒绝写入。
- 角色卡和世界书编辑期间保存锁定；输入在恢复期间禁用。
- 页面导航保存 / 放弃 / 取消，刷新提示；输入框、消息编辑的独立版本化 IndexedDB 草稿。
- 复制标签页通过 Web Locks 分配不同草稿所有权；无该 API 时使用新键复制恢复数据。
- clean draft 读取最新存档；有冲突的 dirty draft 作为独立副本恢复，不覆盖原记录。
- 页面错误边界、预设非法数值和重复标识校验、真实预设编辑往返。
- 浏览器主链路：角色卡导入 → 名称编辑和导航保护 → 预设校验 / 保存 → 内嵌世界书编辑 → 模拟流式聊天 → 消息编辑 → 编辑草稿刷新恢复 → 保存 → 输入草稿跨页面 / 刷新恢复 → JSONL 导出 / 再导入。
- 浏览器故障路径：模拟 chats 写入配额错误 → 保留未保存内容 → 手动重试；生成中导航拦截后取消并停止生成。
- 布局检查：360×640、768×600、1440×480，无 document 横向溢出，输入框可滚动到达。

## 第二阶段日常操作回归

`npm run test:browser` 现在依次运行可靠性链路与 `scripts/daily-workflow-browser-check.mjs`。后者为每个尺寸创建全新 context，实际完成角色卡 / 世界书 / 预设 JSON 导入、编辑保存、筛选、导出和模拟聊天，不使用现有浏览器数据或真实 API。

- 360×640、768×600、1440×480：模态 Tab/Shift+Tab 焦点限制、Escape 未保存确认、取消保留文本、保存按钮可达、保存后焦点归还；document 无横向或纵向溢出。
- 角色标签精确筛选；世界书 / 预设名称搜索、标签、排序与无结果提示；本地标签不进入 ST 导出。
- 新增、复制、删除提示词，全局启用与多排序槽移动；导出断言未知扩展和槽字段保留，删除不留引用。
- 设置页和顶部主题按钮即时同步，不覆盖未保存的模型输入；主题 / 字号独立保存，刷新后保留。
- 自动测试覆盖事务式并发设置修改、主题写入失败、同一帧重复保存拦截以及纯提示词操作。

本地标签保存在 `settings` 的 `assetTags:v1:<kind>:<id>` 中，完整备份会携带，单独 ST 导出不会携带。动态 marker 绑定固定运行时标识，不能复制；普通提示词支持复制。版本号仍为 0.3.0，阶段验收不等同于发布标签。

草稿写入有 300ms 防抖。内部“保存并离开”会等待落盘；刷新 / 关闭浏览器只提供浏览器原生未保存提醒，不能保证进程强杀、设备断电或用户忽略提醒时的最后一次按键已落盘。草稿只存在本机，不会自动上传。
