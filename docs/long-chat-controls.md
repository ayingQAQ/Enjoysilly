# 长对话控制（第四阶段优先批次）

## 上下文预算

预设编辑器可设置上下文上限 `openai_max_context` 和最大输出 `openai_max_tokens`，缺失时分别使用 8192、1024。内置最小预设已有 800 输出设置，继续沿用。输入预算 = 上下文上限 − 输出预留；包含文本估算与请求消息开销，不能替代服务端 tokenizer。

共享组装器只省略最旧的历史消息，保留最近用户消息及其后的回复、系统/角色/世界书等非历史内容。以分批缩短历史的方式减少重复解析，可能比精确最优方案多省略少量历史；原消息、swipe 和存档绝不删除。预览显示省略数量；普通发送发生裁剪时先确认，取消保留输入。必要内容仍超限则阻止请求，并提示调整输入或预设。预算拟合固定宏时间和随机序列，世界书只扫描一次，确认预览仍复用同一请求快照。

## 世界书 timed effects

当前普通聊天共享运行时启用 sticky / cooldown / delay。原生字段和内嵌 `extensions` 字段都读取，不修改资产或写隐藏计时数据。

- 单位：非空、非系统消息的位置；用户和角色消息均计数，临时空助手占位不计数。
- 存在 timed 字段时，在每条用户消息边界重放扫描，当前扫描使用最后一条用户消息的位置及其之前的文本。继续回复不把已生成助手文本当作新的触发边界，避免同轮激活丢失。
- `delay=N`：位置达到 N 才允许激活；0 不限制。
- 在位置 t 激活 `sticky=S`：保持到 t+S（不含终点）；保持期无需关键词/概率再次通过，不延长原到期时间。
- `cooldown=C`：从 sticky 到期后开始；无 sticky 时从 t+1 开始；冷却期不激活。
- 停用和空内容优先；被世界书预算淘汰的条目不启动计时。重复 uid 按来源索引隔离。
- 编辑、删除、swipe、分支和存档恢复均用当前可见历史与当前资产重新计算。重生成使用目标消息之前的历史；继续回复不增加用户边界。预览不会推进任何持久时钟。

这是一套明确可重算的本地语义，不承诺恢复其他软件保存的运行时计时状态。旧资产修改后重放结果也会改变。selective、概率、递归和独立世界书预算仍保持原有默认开关；没有顺带启用。若外部调用方自行启用随机概率并提供非确定随机源，历史重放不保证还原过去随机采样；普通聊天当前没有该组合。

## 搜索与分支

对话标题栏“搜索对话”展开工具条。按当前 swipe 原文进行不区分大小写的字面搜索（不执行正则）；留空浏览全部消息。上一条/下一条切换结果，“定位消息”滚动并聚焦原消息，原编辑入口继续可用。

“从此创建分支”把第 1 条至当前结果保存成新存档，不切换当前会话、不改写原存档。等待当前保存队列，再事务校验来源版本；失败保留原内容，可重试。未保存会话也能分支，来源标记为未保存。分支保存全部未知字段和 swipes；来源 ID、版本和消息位置记录在本地 StoredChat.branch，不塞进 ST JSONL。后续保存保留该来源。

本地来源信息不随单独 ST JSONL 导出；现有通用 ZIP 备份对这种本地来源元数据的保留/重映射留待第五阶段。不要把它当作跨导出文件的分支关系协议。

## 验证与剩余范围

`npm run test:long-chat` 使用全新浏览器 context、本地模拟模型接口。覆盖千条消息搜索定位、独立分支/原档不变/刷新加载、输入超限不发请求且保留草稿、预览历史裁剪、sticky 连续发送和保存刷新后的 cooldown。

本批次不包含用户确认摘要、群聊发言调度改造、虚拟列表或全 tokenizer。千条短文本实测用于建立基线，不代表富 HTML、图片或百万字对话的性能保证。继续使用现有本地草稿防抖；刷新前显式保存可等待落盘。
